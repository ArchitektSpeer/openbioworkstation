# 工作站架构与易用性审查（2026-11-03）

## 结论

现有分层能够继续发展成 Linux 单机可视化生物信息学工作站，无需整体重写。目前更适合熟悉命令行和流程设计的用户，尚不足以证明普通研究者能够独立完成多样本分析。下一阶段应以完整分析任务的成功率为目标，优先补齐可信执行、样本管理和结果浏览，而不是扩大可检索工具数量。

审查依据为根目录 AGENTS.md 和软件工厂设计中的验收证据、风险与独立审查要求。该文件规定开发方法，不替代产品需求。此次未搭建多模型调度器、未修改实现代码。额外使用一个独立代理审查 UI/MCP；属于同模型独立视角，不是跨模型复审。

## 已验证的基础

- UI 与 MCP 通过共享 schema、ToolSpec、编译器和 RunManager 操作同一工作区，核心层不依赖 Qt。
- 会话有稳定 UID、原子保存和乐观修订检查；编译有端口、必填输入、环检测和路径许可检查。
- Snakemake 承担实际调度；后台监督进程持久化状态，并保存运行会话和 Snakefile。
- 本次 `.venv/bin/python -m pytest -q`：17 passed in 15.33s，包含真实 Snakemake 复制文件链路；`.venv/bin/ruff check .` 通过。复制链路不等于真实生物学分析验收。
- `.venv/bin/python -m validation.ui_smoke` 通过：加载 3 个节点、2 条连线，保存后 revision 从 1 变为 2；这是 offscreen 加载保存检查。

## 发现（按优先级）

1. **P1：自动封装在审核之前执行生成命令。** `glue/wrap_service.py:273-277` 存储未审核定义后直接调用 trial_run；`:134-140` 用当前用户权限执行 `conda run ... bash -lc`。临时 cwd 和 Conda 环境不是文件系统或网络沙箱；格式验证只约束占位符，不限制 shell 字面命令。应在宿主执行前完成命令审查，或先建立限制挂载、网络、资源与进程生命周期的隔离试运行环境。此项为静态调用链证据，未执行恶意命令。

2. **P1：审核状态没有绑定定义版本。** `glue/wrapper_registry.py:588-603` 按 tool_id 保存审核；`:535-536` 对后续同 ID 定义直接覆盖为 reviewed=True。临时目录复现：审核 v1 → 用 store_definition 保存不同 shell 的 v2 → 重建索引，存储返回 reviewed=False，但 registry.get 返回 True。应以定义、依赖和执行来源摘要绑定审核，变更后失效。

3. **P1：历史运行与浏览结果未形成一致快照。** `ui/workstation_window.py:1161-1171` 选择历史仅切换 ID、日志与颜色；`:1052` 结果路径仍由当前图编译。`glue/snakemake_bridge.py:139,165,191` 输出、节点日志和 benchmark 共用工作区路径，重跑可能覆盖旧产物；`:405-415` manifest 未保存工具定义、环境锁或输入输出摘要。应以 run_id 作为浏览上下文，明确区分历史快照与当前编辑，并为产物建立版本或失效检测。

4. **P1：MCP 无法接续和修复已有分析。** `mcp_server/bio_mcp.py` 注册 9 个工具，但缺少读取当前图/完整工具 schema、修改节点、删节点、断线、取消及历史查询。新 Agent 会话无法通过该接口恢复已有节点 UID，也不能原位修正参数。应提供带 revision 的共享应用服务，由 UI/MCP 共用，支持完整编辑与恢复闭环。

5. **P2：局部执行与结果预览被无关草稿阻塞。** `glue/snakemake_bridge.py:348` 先编译整个图，之后才选目标子图；编译器 `:107-116` 校验所有工具。临时目录复现：有效链旁增加未连线的 copy 节点，即报“缺少必填输入”，有效链不能编译。UI 输出预览同样依赖整图编译。应先选择执行闭包，并让既有结果浏览独立于当前草稿合法性。

6. **P2：输入节点标签不保证实际输入类型。** `glue/snakemake_bridge.py:95-104` 只验证路径许可和文件存在；端口格式来自节点类型。临时目录复现：FASTQ 输入节点指向普通文本，编译仍成功。MCP 添加输入虽返回检查结果，但未据失败拒绝保存。建议运行前集中执行轻量格式和必需索引检查，明确区分快速检查与全文件验证；参考版本和样本配对属于更高层语义约束。

7. **P2：当前 MCP 验证证据不成立。** 实际运行 `.venv/bin/python -m validation.mcp_stdio_client` 在 `validation/mcp_stdio_client.py:40` 失败：断言 7 个工具，实际为 9 个，尚未进入后续图与运行检查。仓库未见 `.github` CI 配置，应把适用质量检查自动化，并按工具名称/契约验证。17 项 pytest 通过不能替代该接口验收。

## 产品能力与架构调整

| 能力 | 现状 | 建议 |
| --- | --- | --- |
| 可视化构图 | 节点、强类型格式标签、三种执行模式已具备 | 保留 NodeGraphQt，增加模板、分组、折叠与局部验证 |
| 多样本 | 独立链复制；无样本表和分组契约 | 增加 SampleSheet、配对/批次/分组与参考数据模型，在编译层展开，UI 展示流程及样本状态 |
| 参数配置 | ParamSpec 仅 name/default/description，UI 使用文本框 | 增加类型、范围、枚举、必填、单位、依赖和文件选择，生成受约束表单 |
| 资源管理 | 主要有 cores/threads | 在任务模型及编译层增加内存、磁盘、运行时与环境预检，UI 提供可理解的估算和错误指引 |
| 结果工作台 | 文本统计、有限记录预览、外部打开文件 | 建立 artifact 类型，提供 QC HTML、表格、图和运行比较入口；基因组浏览按已选分析场景接入 |
| 工具扩展 | 目录索引广，真实可用性依赖本机定义和环境 | 区分可检索、可安装、已封装、已审核、已验证；优先维护可重复验收的常用流程 |
| Agent 协同 | 共享磁盘会话，有冲突保护 | 增加统一应用服务和完整 MCP 编辑接口，明确未保存 UI 草稿与磁盘修订 |

推荐保留 UI/MCP → 共享应用服务 → 领域模型/编译器 → Snakemake/运行监督器这条路线。补充 Sample、Reference、WorkflowTemplate、Run、Artifact、ValidationRecord 等显式契约。不要为了易用性重写调度器，也不必为当前单机场景引入分布式服务。UI 单文件已达 1465 行，可随这些功能拆分控制器、参数表单、运行及结果视图，避免业务规则继续堆入窗口。

## 建议验收顺序

1. **可信执行闭环**：先修复审核与试运行边界、历史结果绑定、局部执行和 MCP 验证；同一工具定义变化必须撤销旧审核，历史结果不得静默指向新产物。
2. **一个面向研究者的完整流程**：选定 FASTQ QC → 过滤 → 参考比对 → BAM 统计；支持样本表导入、双端配对检查、环境预检、参数表单、失败恢复和结果报告。以若干真实样本及固定的小型夹具分别验收。
3. **易用性和可复现性**：让不熟悉 CLI 的目标用户从空工作区完成流程，记录卡点、错误恢复和用时；修改参数重跑后仍能辨认旧结果，重启后可由 UI 或 Agent 接续任务。
4. **再扩展生态和开发自动化**：模板、跨流程 artifact、性能与更多工具逐步增加。多模型软件工厂改善开发组织，不能代替工作站自身的科学与交互验收。

## 验证限制

本次没有执行完整真实生信工具链、真实 Agent 客户端交互、用户可用性测试或规模性能评测。offscreen UI smoke 通过仅证明加载和保存，不证明完整桌面交互易用。所有临时复现仅使用合成文本和本地定义；未进行网络模型调用或生产操作。

用户随后明确产品定位：复杂操作交给外部 Agent，用户通过界面观察、查看配置并修改；未审核工具允许由用户及其 Agent 自主管理。因此，上文第 1 项“审核前执行”按这一授权模型改为执行策略和可追踪性要求，不再以强制人工审核作为产品门禁。
